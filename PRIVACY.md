# Privacy Policy — ClipVault

**Last updated: 26 August 2026**

ClipVault does not collect, transmit, or share any data.

## What ClipVault stores

ClipVault stores the text you copy, along with the name of the application it
was copied from and the time it was copied. All of it stays on your Mac, in
`~/.clipvault/`.

Those files are given owner-only permissions (`0600`), so other user accounts
on the same Mac cannot read them.

## What ClipVault does not do

ClipVault has no network functionality of any kind. It does not:

- create an account or ask you to sign in
- sync anything to any server
- use analytics, telemetry, or crash reporting
- contain advertising or third-party SDKs
- send your data anywhere, to anyone

There is no networking dependency anywhere in the project. You can verify this
yourself in the source.

## Content that is never recorded

macOS lets an application mark content on the pasteboard as sensitive.
Password managers do this for passwords. ClipVault checks for these markers and
skips that content entirely — it is never written to disk:

- `org.nspasteboard.ConcealedType` — passwords and other secrets
- `org.nspasteboard.TransientType` — content not meant to be retained
- `org.nspasteboard.AutoGeneratedType` — machine-generated content

If ClipVault cannot read the pasteboard's markers for any reason, it treats the
content as sensitive and does not record it.

Non-text content — images, files — is never recorded, because ClipVault only
reads text.

## Your control

- **Delete one entry** — "Delete Current Entry" in the menu (⌘⌫)
- **Clear everything** — "Clear History" in the menu (⇧⌘⌫)
- **Limit what is kept** — set a history limit in Preferences; older entries are
  pruned automatically
- **Stop recording** — quit ClipVault; it records nothing while not running
- **Remove everything** — delete the app, then delete `~/.clipvault/`

## Children

ClipVault is not directed at children and collects no data from anyone.
